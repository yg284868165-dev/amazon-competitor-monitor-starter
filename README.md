# Amazon 美国站竞品监控器

通过本机 Chrome 访问 Amazon 前台页面，监控竞品详情、关键词自然位/广告位和 Best Sellers 前 100。无需 Amazon API，公开页面字段不要求买家账号。

## 分享版说明

这是一份不含任何预设产品、竞品 ASIN、关键词、BSR 类目或新品筛选词的干净版本。定时采集和微信通知默认关闭。

首次使用请先按下文安装依赖，然后双击 `Amazon竞品监控.app`，在“产品项目”页至少新建一个项目，再填写竞品、关键词和 BSR 类目。确认手动采集正常后，再按需开启定时任务和微信通知。

## 多产品监控项目

- `config/projects.xlsx` 定义产品项目、显示名称和美国邮编。
- 竞品、关键词和榜单通过 `project_id` 归属到对应产品。
- 项目 ID 只能在“产品项目”页修改；保存后会级联更新竞品、关键词、BSR 类目、新品筛选规则、历史数据库和指定项目的定时配置。
- 每个产品项目生成独立固定报告，数据和变化不会串项目。
- 监控清单按表格行顺序执行，没有 `priority` 字段。
- 遇到验证码会记录诊断信息并按既定重试次数处理，不尝试绕过。

## 本地管理页面

推荐双击项目根目录中的 **Amazon竞品监控.app**。它带有独立应用图标，不显示终端窗口，会自动启动本地服务并打开管理页面；运行期间图标会保留在 Dock，再次点击即可重新打开页面。退出 App 时会一并停止由它启动的管理服务。App 必须和项目文件保留在一起，但可以把它拖到 Dock 栏创建快捷入口。因为项目位于桌面目录，首次启动若 macOS 询问是否允许访问桌面文件，请选择允许。

也可以双击 `start_web.command`，或在终端运行：

```bash
.venv/bin/python web.py
```

系统会自动打开 `http://127.0.0.1:8765`。页面仅绑定本机地址，不会暴露到局域网或公网。可以在页面中：

- 管理产品项目、竞品 ASIN、关键词和 BSR 类目；
- 批量添加竞品 ASIN 和关键词，并按项目 ID、启用状态组合筛选；
- 修改、安装和卸载定时任务；
- 手动启动全部或单项采集；
- 查看最近运行状态；
- 下载各产品项目的主报告，以及跨项目的昨日日报和上周周报。
- 配置、测试和安装 Server酱微信日报与周报。
- 设置新品同类/排除关键词，并人工确认待定的 BSR 新品候选。

页面直接读写现有 Excel 配置，保存时会执行字段校验。请避免同时在 Excel 中打开配置文件并在网页中保存。

## 首次运行

克隆仓库后先创建 `.venv` 并安装依赖：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
```

本机 macOS 11 使用 `config/settings.json` 中指定的 Google Chrome，因为新版 Playwright Chromium 不兼容该系统版本。

浏览器首次打开 Amazon 时会设置并确认项目邮编。地址请求后的瞬时页面跳转如果产生 `net::ERR_ABORTED`，系统会按 `initialization_attempts` 自动重试，默认最多尝试3次并逐步延长等待；这部分与商品、关键词和榜单页面内部的采集重试相互独立。正式采集遇到 `ERR_FAILED` 等页面异常时，不会继续复用 Chrome 错误页，而是关闭标签页、等待5秒/10秒并用新标签页继续失败项。

## GitHub 备份

项目使用 Git 管理。如果你在自己的 GitHub 账号下维护此工具，请将 `origin` 设置为你自己的仓库。

每次完成并验证开发改动后，使用：

```bash
git status --short --branch
git add <本次改动的文件>
git commit -m "说明本次改动"
git push
```

GitHub 仓库保留源码、测试、文档和配置。`data/monitor.db`、锁文件、日志、诊断截图/HTML、生成报告、虚拟环境和缓存由 `.gitignore` 排除，因此 GitHub 备份不包含采集历史数据。Server酱 SendKey 仍只保存在 macOS 钥匙串。

## 手动执行

```bash
.venv/bin/python run.py product --project my_product
.venv/bin/python run.py search --project my_product
.venv/bin/python run.py bestseller --project my_product
.venv/bin/python run.py all --project my_product
```

管理页“最近运行”中，状态为 `partial` 或 `failed` 的批次仍可点击“重试失败项”。系统只重跑该批次最终失败的 ASIN、关键词或 BSR 类目，并将结果保存为新的“失败项重试”批次；原批次状态作为历史记录保留。每个批次会在打开浏览器前保存完整目标清单，因此断网发生在首个页面或邮编初始化阶段时，手动及自动重试仍能找回全部目标；旧的无清单失败批次会从当前仍启用的项目配置重建目标。重试批次也会记录来源关系，即使重试本身在浏览器初始化阶段整体失败，仍可再次找回原失败目标。

正常采集结束后如果存在 `partial` 或 `failed` 批次，程序会保持电脑唤醒，在整轮所有项目结束后等待5分钟，只对失败目标自动精准重试一次；不会无限循环。若等待期间已经人工重试成功或正在重试，自动流程会识别并跳过，避免重复采集。自动重试在运行记录中显示为“自动失败项重试”。开关和等待秒数位于 `config/settings.json` 的 `auto_retry` 节点。管理页运行期间每3秒刷新，空闲时每15秒检查一次，因此能自动发现延迟启动的重试并在结束时更新报告列表。定时采集发生异常时，系统会等这次自动重试结束再通过 Server酱通知：已恢复时明确说明无需操作，仍失败时列出失败目标类型和数量；如果断网导致通知无法发送，消息会保存在数据库并在后续定时采集时补发。手动采集不会触发这类系统告警。

不写 `--project` 或使用 `--project all` 会依次运行所有已启用项目。报告固定输出到 `output/reports/<项目名称>/`，文件名包含项目名称，例如 `示例产品_Amazon竞品监控.xlsx`；每次运行覆盖更新当前状态并在同一工作簿保留最近30天历史。原“变化提醒”工作簿因与主报告“今日重点”重复已取消；管理页面会根据数据库实时生成可下载的昨日日报和上周周报 Excel。异常截图、HTML 和日志分别位于 `output/screenshots/`、`output/html/` 和 `output/logs/`，最近30天历史数据位于 `data/monitor.db`。

每次正常采集或失败项重试开始前都会自动执行本地保留策略：商品、关键词、BSR、变化、运行、新品候选和通知等数据库历史、异常截图与HTML、运行日志统一滚动保留30天。过期数据库记录删除后会自动回收数据库空间，固定Excel报告不会被删除，并会在本次采集结束时按剩余30天数据重新生成。保留天数配置位于 `config/settings.json` 的 `retention` 节点。

## 每日多次执行与整体日报

同一天可以执行多次。每次采集保存独立快照，但不会产生多份主报告：

- `今日汇总` 聚合当天全部商品快照，包括首末价格、最高最低价、首末/最佳/最差 BSR、Rating 增量、Coupon、Deal、企业价和库存异常。
- `今日关键词汇总` 聚合当天每次关键词采集，展示批次数、最佳和最新自然位/广告位。
- `今日重点` 汇总当天值得阅读的内容、价格、促销和合格新品变化；普通单次排名波动不会进入重点提醒。
- 商品统一显示“内部名称/采集标题 + 品牌 + ASIN”，变化项目和摘要前置，来源移到后面，并提供可点击的 Amazon 商品链接。
- `竞品历史`、`关键词排名历史` 和数据库继续保留最近30天的跨日明细。

主报告默认只展示 `今日重点`、`趋势观察`、`新品雷达`、`竞品当前状态` 和 `采集异常` 五个页面。今日汇总、关键词汇总、竞品历史、关键词历史、BSR原始榜单和运行记录仍保留在同一工作簿中，但默认隐藏，可在 Excel 中取消隐藏。

## 商品风险与类目变化

商品详情采集同时识别 Amazon 前台的高退货率标签、商品页面状态以及大小类目名称。高退货率标签出现或消失、大小类目名称发生变化，都会进入当日日报和 Excel“今日重点”；即使同一天内恢复原状，日报仍会保留完整过程。旧历史数据的高退货率字段为空时，第一次新采集只用于建立基线，不会误报为标签变化。

商品页连续经过全部配置重试后仍显示 Amazon Page Not Found、Dogs of Amazon 等明确404文案时记为“页面变狗”；出现 `This item/product is no longer available` 等明确永久不可用文案时记为“商品下架”。这两种状态及后续恢复都会进入日报。普通 `Currently unavailable` 仍按库存“断货”处理，避免把暂时缺货误报为下架。类目名称直接切换会立即记录；类目区域完全消失时需要连续两次采集缺失才确认，减少页面模块偶发未加载造成的误报。

## 排名趋势

大小类目BSR和关键词自然排名趋势统一使用截至周日的完整自然周，并在周一周报及 Excel“趋势观察”中展示，不进入日报。系统先对每天多次采集取中位名次，再计算近7日（1周）、14日（2周）和28日（4周）趋势：7日要求至少5个有效日且至少60%的日间移动方向一致；14日比较两个完整周的周中位数；28日比较第一周与第四周，且至少两次周间移动方向一致。

大类目BSR需变化达到“20名和周期中位排名10%中的较大值”；小类目BSR按“变化至少5名或达到周期中位排名10%”判断；关键词自然排名至少变化5名。百分比只用于内部识别明显趋势，周报仅展示“从多少名提升/下降到多少名”。自然排名未进入配置页数时不会虚构具体排名。

广告位不再按日取中位数或输出7/14/28日“明显趋势”。每次关键词采集的原始广告位、未观察到广告和采集失败都会保留，周报 Excel 以美国西部时间提供近28天“广告分时轨迹”和“广告采集明细”。微信周报只概括在至少3个有效日重复出现的分时规律，将观察事实与可能解释分开：中可信度要求至少3个可比日且60%以上重复，高可信度要求至少4个可比日且75%以上重复。推测仅作为竞价策略线索，不把广告拍卖波动直接断言为竞对调价。

## BSR新竞争对手雷达

BSR前100中的每个ASIN都会按当前榜单重新检查，不再要求它必须是相较上一次采集“首次进榜”。已经存在于该项目监控ASIN配置中的商品（包括已停用的行）会被排除。对其余商品，系统访问详情页读取标题、品牌和 `Date First Available`，再依据 `config/new_product_rules.json` 中每个项目的包含/排除关键词判断是否为同类产品。只有同类且上架天数小于该项目所设期限的未监控ASIN才会生成一次性的新竞争对手提醒。

无法判断、缺少上架日期或没有命中关键词的商品进入管理页面的待确认列表，可以人工标记为同类或非同类；超过期限的商品只记录、不提醒。每个合格ASIN只提醒一次，避免因每日重复出现在榜单中而反复推送。

新品雷达的上架日期可以人工填写或修正，并区分“自动采集”和“人工填写”来源。保存后立即重算上架天数与筛选状态：达到项目期限时自动归为超过期限；期限内且已确认为同类时可生成一次性新竞争对手提醒。清空人工日期后会恢复为待获取状态。

## 定时任务（macOS）

编辑 `config/schedule.json`：

```json
{
  "enabled": true,
  "times": ["08:00", "12:00", "16:00", "20:00"],
  "task": "all",
  "project": "all",
  "wake_enabled": true,
  "wake_lead_minutes": 2
}
```

时间使用 24 小时制，可以自由增加、删除或修改。保存后安装：

```bash
.venv/bin/python schedule.py install
```

建议直接在管理页面修改并点击“安装 / 更新”。启用自动唤醒时，首次安装会弹出 macOS 管理员密码窗口；系统为每次采集提前唤醒。LaunchAgent 直接启动 Python，Python启动后再通过 `caffeinate` 阻止整机睡眠，避免外层包装进程丢失 Desktop 访问权限。合盖状态仍不能保证执行。修改时间后需要重新安装，让系统载入新计划。其他命令：

```bash
.venv/bin/python schedule.py status
.venv/bin/python schedule.py run-now
.venv/bin/python schedule.py permission-test
.venv/bin/python schedule.py uninstall
```

`permission-test` 使用真实 LaunchAgent 验证后台 Python能否读取 Desktop 项目和 macOS钥匙串，但不会访问 Amazon或发送微信。定时日志位于 `output/logs/scheduler.stdout.log` 和 `scheduler.stderr.log`。程序带非阻塞锁，如果上一次任务尚未完成，下一个时间点不会同时启动第二份采集。可用 `.venv/bin/python schedule.py status` 同时核对普通任务和自动唤醒是否安装。

## 微信日报与周报

管理页面“微信通知”支持通过 Server酱发送两条相互独立的简报：日报按配置时间发送前一自然日的商品内容与运营事件及合格新品，不再展示任何排名趋势；周报固定在每周一10:00发送，完整复盘上一个自然周内实际进入过日报的全部重点变化，并汇总评价数量、大小类目BSR和关键词自然排名的近1/2/4周趋势，以及达到中/高可信度的广告分时观察。周报按项目和商品合并组织，并区分“截至周末仍保持变化”和“周内已恢复原状态”。评价数量不进入日报。概览页“报告下载”可随时下载按同一口径生成的完整昨日日报和上周周报 Excel；日报展示数量可配置，微信周报和周报 Excel 均展示全部重点内容，周报 Excel 另外保留近28天完整广告分时证据。两种 Excel 中的 ASIN 商品链接都可以直接点击打开。

广告分时观察按美国西部日期归档，而周报按中国本机时间周一10:00发送。这个时间点对应美国西部周日傍晚，因此微信周报会使用发送时已经完成的采样，尚未发生的周日深夜档不会被虚构或回填；周一14:00采集结束后再从管理页下载周报 Excel，才会包含该美西自然周最后一个深夜档。若以后要求微信周报也覆盖完整的美国西部周一至周日，应把发送时间调整到中国时间周一15:00以后。

日报 Excel 中的“采集时间”是程序检测到该变化的采集时刻，不代表竞品在 Amazon 上实际修改的精确时间。

日报把价格、Coupon/Deal、企业价、库存、购物车卖家、跟卖数量、发货方、高退货率标签、商品页面状态和类目名称视为事件型字段：即使一天结束时恢复原值，发生过的过程仍会合并保留。例如短时降价显示首价、最低价与末价；库存统一为有货/低库存/断货并提示断货及恢复；跟卖入口连续两次未出现后确认消失。标题、图片和文案等状态型字段仍只提醒日终净变化。

Coupon、Deal 或企业价从有内容变为空时会明确提示活动取消。Deal 同时识别商品页可见的 Prime Day、Prime Big Deal Days、Prime Exclusive、黑五、网一和秋促等明确活动标签，不扫描页面脚本中的预置文案，以减少误报。竞品当前状态和历史页保留 5至1 星评价占比；当 rating 星级发生变化时，日报的变化摘要也会附带当前各星级占比。Ships From变化进入日报并同步到Excel当前状态；主图替换导致主图和图片集同时变化时只提醒“主图变化”，只有副图发生变化时仍提醒“产品图片集变化”。SendKey 保存在 macOS 钥匙串，不写入项目文件、数据库或日志；日报和周报分别使用独立 LaunchAgent，不影响 Amazon 采集时间。

企业价目前仅采集 Amazon 向未登录 Chrome 会话实际返回的可见内容。如果某个价格只对已登录的 Amazon Business 买家展示，当前版本无法获取；完整覆盖这类账号专享价需要另行增加专用的持久登录浏览器配置。

首次设置时，在管理页面本地粘贴 `SCT` 开头的 SendKey，点击“保存并发送测试”，手机确认收到后再点击“安装 / 更新定时发送”。安装动作会同时安装日报和周报；修改日报发送时间后也需要重新安装。页面可以分别立即发送昨日摘要和上周周报；“日报最多展示变化数”仅限制微信日报，周报始终展示全部复盘、评价与趋势内容。两种简报共用“无变化时是否发送”设置。

命令行状态与日志：

```bash
.venv/bin/python notify_schedule.py status
.venv/bin/python notify_schedule.py install
.venv/bin/python notify_schedule.py uninstall
```

日报日志位于 `output/logs/notification.stdout.log` 和 `notification.stderr.log`，周报日志位于 `weekly-notification.stdout.log` 和 `weekly-notification.stderr.log`。最近发送结果同时记录在数据库的 `notification_logs` 表中。微信消息只提供简短摘要，本机 Excel 报告不会上传到 Server酱。

## 配置清单

- `config/projects.xlsx`：`enabled, project_id, project_name, postal_code`
- `config/competitors.xlsx`：`enabled, project_id, asin, internal_name, brand, remark`
- `config/keywords.xlsx`：`enabled, project_id, keyword, pages`
- `config/categories.xlsx`：`enabled, project_id, category_name, category_url, max_rank`

修改 Excel 后直接再次执行，不需要修改代码。运行时请关闭正在编辑的配置文件，以免 Excel 锁定文件。

## 结果解释

- `organic_rank` 是剔除 Sponsored 后的自然位。
- `ad_rank` 是广告商品之间的顺序。
- `absolute_position` 是页面实际商品卡片顺序。
- 某次页面没有看到广告，只代表该邮编、设备和采集时刻没有观察到，并不证明竞品停止投放。
